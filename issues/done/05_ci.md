## PR と main への push で、board のテストと usage の生成物のずれを CI で確かめる
id: 05
branch-slug: ci
status: close
depends: 01
type: feat
対象: .github/workflows/ci.yml（新規。workflow を2つに分けるなら2本）、CLAUDE.md
目的: いまは CI が無く、テストは手元で回した件数を PR の本文に書いて済ませている。board のテストと usage の生成物のずれを機械で確かめ、実装に関わるファイルが変わったときだけ動かす。
内容: リポのルートに workflow を置き、`pull_request` と main への `push` で動かす。board のテストと usage の生成物のずれの2つのジョブに分け、それぞれ変更のパスで絞る。`paths` は workflow の `on` ではジョブごとに分けられないので、workflow を2つに分けるか、`dorny/paths-filter` のような変更の判定を挟む。どちらにするかは実行者が決める。`CLAUDE.md` の「PR の本文に通った件数を書く」を CI に任せる形に直す。
対象外: `usage/.github/workflows/usage.yml`（取り込む側へ配る雛形で、このリポでは動かない）。`board/scripts/make_samples.py` の生成物（`.xlsx` は作るたびに中の日時が変わり、差分で比べられない）。main を守るブランチの設定（`paths` で絞ったジョブを必須にすると、動かなかった PR が待ち続けるので、CI が落ち着いてから決める）
仮定:
- 01 で `ladder/docs/personas.md` を board が読まなくなるので、board のテストを動かすパスに含めない（そのため `depends: 01`）
確認:
- board のテストのジョブは、Python 3.12 で `board/requirements.txt` と `board/requirements-dev.txt` を入れ、`cd board && python -m pytest -q` を回す。`actions/setup-python` の `cache: pip` が効いている
- board のテストのジョブは、次の変更で動く：`board/` の下の `.md` 以外、`ladder/docs/ladder.md`、`usage/tools/usage/` の `.py`、`usage/tools/usage/claude-code/data/`、CI の workflow そのもの
- usage のジョブは `python usage/tools/usage/claude-code/render.py` を回し、`git diff --exit-code usage/tools/usage/claude-code` で差分が出ないことを確かめる
- usage のジョブは、次の変更で動く：`usage/tools/usage/` の `.py`、`usage/tools/usage/claude-code/data/`、`usage/tools/usage/claude-code/README.md`、CI の workflow そのもの
- この Issue の PR で CI が走り、緑になる
- わざとテストを1件落とした commit で赤になる。その commit は戻す
- `render.py` だけを直して MD を作り直さない commit で、usage のジョブが赤になる。その commit は戻す
- `board/README.md` だけ、`ladder/README.md` だけを変えた変更では、どちらのジョブも動かない
- `ladder/docs/ladder.md` だけを変えた変更では、board のテストが動く
- `CLAUDE.md` が「テストは CI に任せる。CI が動かない変更（文書だけなど）では件数を書かなくてよい」という形になっている
人が見るもの: PR の画面で、2つのジョブが動いたこと・動かなかったことを確かめる
