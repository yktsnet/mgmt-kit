# Guarantee Ledger

Board が外へ約束している振る舞いと、それを守るテストの一覧である。約束が破れればテストが落ちるので、
ここに書いたことは気づかないうちに実装とずれていかない。**ここに載っていない振る舞いは約束ではなく、予告なく変わりうる**。
[board/docs/decisions.md](../../board/docs/decisions.md) と同格の文書である。

- 対象: Board の画面と API の振る舞い（役割ごとに見せる範囲を含む）、評価と面接のシートの読み方、段階の決め方、設定の規則、利用データを画面に添える規則。テストが関数を直接呼んでいても、使う人から見える規則なら載せる。シートの形の正本は [board/docs/sheets.md](../../board/docs/sheets.md) で、ここにはそのうちテストが固定しているものだけを載せる
- 対象外: 画面の見た目と幅（Playwright のテスト）、`ladder/` と `usage/` の生成物、値の変換などの補助の関数、DB の移行
- 目的: いま何を約束しているかを1か所で読む。変更の前に、守らなければならない約束をここから引く。テストの無い約束を Gaps に残す
- 分け方: 約束の対象ごとに1ファイル。対象は使う人から見える単位（ログイン、評価のページ、現在地など）で、そのページを誰が見られるかも同じファイルに書く。テストファイルや Issue の単位では分けない。新しい対象を作ったときだけファイルを足す
- 書き方: 各ファイルに「保証｜対応テスト」の表を1つ置き、1行に約束を1つ、宣言文で書く。出典・経緯・設計の理由は書かない（decisions.md に書いてある）
- 引き方: 変えるコードのテストの関数名で台帳を検索し、当たったファイルから約束を引く。テストが落ちたときは、落ちたテストの関数名で検索すると、破れた約束が分かる
- 運用: 変更の前にこの README を読み、変更が触れるファイルの約束を読んで、破らないことを確かめる。約束を足す・変える・消すときは、保守する人が承認した文のまま、該当するファイルの表に行を足す・直す・消し、対応テストも同じ変更で直す。Issue や作業ごとにファイルや節を起こさない。テストの無い約束は Gaps に書き、テストを足したら表へ移す。台帳とテストのずれは、ときどき全体を突き合わせて棚卸しする

## Gaps

テストが無く、まだ約束として保証していないもの。対象の順に並べる。

- login: ID トークンのドメイン（`hd`）が `BOARD_ALLOWED_DOMAIN` と違うアカウントを拒むこと。テストは `hd` の無い個人のアカウントだけを見ている
- login: デモでないとき、ログインの Cookie に Secure が付くこと。テストは https の前提で回していて、属性を見ていない
- login: `BOARD_SESSION_KEY` が空のとき、起動のたびに鍵を作り直すこと。どのテストも鍵を与えて起動している
- login: `BOARD_SOURCE` が `drive` のとき、デモのログインとデモの在籍者を使わないこと。テストは `BOARD_DEMO=0` だけを見ている
- review-pages: 評価のページに、シートの最終の編集日時と編集した人を出すこと。テストは Drive の編集者を与えていない
- review-pages: 評価のページと一覧に、評価がどの版で付いたかを出すこと。テストは版の表示を見ていない
- review-status: 状態の切り替えとメモの記録に、日時を残すこと。テストは誰がしたかだけを見ている
- now: 在籍者が2人以下のとき、画面に平均を出さないこと。テストは平均を作る関数だけを見ている
- hiring: 選考の段階の記録に、日時を残すこと。テストは誰がしたかだけを見ている
- hiring: 候補者の未観測の軸を「次に聞く」に出すこと。テストは未決定の軸だけを見ている
- hiring: 採用の画面に利用データを出さないこと。どのテストも採用の画面の利用データを見ていない
- hiring: 候補者の1人のページに、面接・判定・記録を出すこと。テストは開けるかどうかだけを見ている
- hiring: いない候補者の1人のページが 404 になること。テストが無い
- sync: シートを書き換えてから `BOARD_SYNC_INTERVAL` の秒数のあとに画面を開くと、その中身が画面に出ること。テストは間隔を 0 にし、読み直しを関数で見ている
- sync: 読めなかったファイルを、画面に区画として出すこと。テストは読み込みの結果だけを見ている
- sync: 画面の右上に、どこからいつ読み込んだかを出すこと。テストが無い

1ファイルの保証が21行以上になったら、対象の中の小さな対象でファイルを分ける。行を足して21行以上にした変更の中で分け、新しいファイルを上の一覧に載せる。
